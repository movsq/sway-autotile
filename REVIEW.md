## Review of `aeca513..5c9833b`

The requested outcomes were to replace the autotiling-rs geometry comparison with direct checks that each new window halves the focused one, add an Arch PKGBUILD, and put the README through a writing and style pass. I treated “always” as applying to settled opens beside an ordinary tiled window, including after startup, move, and resize. The existing exceptions for floating, fullscreen, tabbed, and stacked windows still apply. The cleanup and split timing is an implementation choice, with directional moves required to keep working.

### Findings

- **P2 — The first open after daemon startup can resize unrelated windows.** At [the initial daemon pass](https://github.com/movsq/sway-autotile/blob/5c9833b/sway-autotile#L203), the daemon only cleans up. In a fresh 2560×1440 headless Sway with the test configuration, open terminals `a` and `b` before launching the plain daemon, focus `a`, launch the daemon, wait for startup, and open `c`. The two 1268×1424 windows become three roughly 843×1424 columns. The expected result is two 1268×708 windows in `a`'s old rectangle, with `b` unchanged. The CLI test starts its plain daemon after a one-shot split and subsequently refocuses before checking.
- **P2 — Opening after a move can divide the parent.** [The move handler](https://github.com/movsq/sway-autotile/blob/5c9833b/sway-autotile#L208-L210) leaves the current tile unwrapped so repeated moves can work. Start the daemon, open `m1` and `m2`, focus `m1`, run `move right` twice, then open `m3` without a focus change. The new window joins a three-column layout and `m2` shrinks. The expected result is a vertical split within `m1`'s 1268×1424 rectangle. The README describes this exception, and scenario 12 refocuses before it opens a window. A headless probe restored the geometry by wrapping the old tile on the new-window event and moving the new tile next to the old one inside that wrapper. The probe also preserved the sibling of an 1800-pixel-wide tile.
- **P2 — Resizing the focused window can leave the split pointing the wrong way.** [The split is chosen on window events](https://github.com/movsq/sway-autotile/blob/5c9833b/sway-autotile#L203-L210), and Sway emitted no window event for the resize in this reproduction. With the daemon running, open `a` and `b`, focus `a` while it is tall, run `[con_id=<a>] resize set width 1800 px`, then open `c` without changing focus. The pair stacks as two 1800×708 windows. The expected pair is two 896×1424 windows side by side. The resize suite resizes an unfocused window and then focuses it, which refreshes the split.
- **P3 — The README's command for starting the daemon in an existing session uses the manual install path.** [The Configuration section](https://github.com/movsq/sway-autotile/blob/5c9833b/README.md#L83-L98) gives both install paths for the startup config, then only gives `~/.local/bin/sway-autotile` for `swaymsg exec`. The archive produced by the PKGBUILD contains `/usr/bin/sway-autotile`, so the supplied command fails for a package-only install.
